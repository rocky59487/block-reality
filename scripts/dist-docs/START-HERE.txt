Block Reality — Structural Preview
==================================

Structural analysis for Minecraft, solved by a real finite element engine.
Requires Minecraft 1.20.1 with Forge 47.x.


INSTALL
-------
Put blockreality-*.jar in your mods/ folder and launch the game. That is all:
the analysis engine is inside the jar and unpacks itself the first time it is
needed.

On first use it appears at

    <game directory>/blockreality/engine/<hash>/br-sidecar[.exe]

The folder is named after the binary's SHA-256, so a mod update lands beside the
old engine instead of overwriting it, and a half-written file can never be taken
for a good one. Nothing is downloaded: those bytes were already in the jar you
installed, their hash is recorded beside them, and anything that does not match
is refused rather than run. A binary you put there yourself is never touched.

Windows and Linux on x86-64. On macOS or ARM the mod loads and plays normally
with analysis disabled, and says so.

The installer scripts in this archive are optional and do the same thing plus
copying the loose engine; use them if you would rather not find mods/ by hand:

    install.bat "D:\games\my-instance\.minecraft"
    ./install.sh ~/.minecraft

    install.bat --list        list what was found, install nothing
    ./install.sh --list

The directory to give it is the game directory: the one containing mods/ and
saves/.


CONTENTS
--------
  blockreality-*.jar     the Forge mod - this alone is a complete install
  br-sidecar.exe         the same Windows engine, loose, for checking or for
                         running the solver outside the game
  br-sidecar             the same Linux engine, loose
  install.bat/.sh        optional installer
  SHA256SUMS.txt         hashes of every file in this archive

The loose engines are byte-identical to the copies inside the jar, and a build
gate holds them to that. Both are reproducible: building from source on another
machine gives the same hashes.

FrameCore is statically linked into br-sidecar, so there is no separate library
to install. br-sidecar runs as its own process rather than as a library loaded
by the mod: a fault in the C++ costs one analysis rather than the server and the
save.

The mod looks for the engine in this order: the config file, -Dbr.sidecar, the
BR_SIDECAR environment variable, the copy bundled in the jar, the game
directory, then PATH. Explicit settings come first, so a path you chose is never
quietly overridden.


IN GAME
-------
Creative tab "Block Reality": nine structural blocks and the Stress Glasses.
A block's token decides which ELEMENT it becomes — beams and plates are
different element types, not one type in different colours:

  Structural Steel (three sizes)   6-DOF beams: 200x400, 150x300, 100x200 mm
  Plain Concrete Beam              6-DOF beam, 400x600 mm, unreinforced —
                                   cracks in tension at 3 MPa, as it should
  Timber Beam                      6-DOF beam, 140x240 mm sawn section
  Brick Pier                       6-DOF beam, 230x350 mm masonry pier
  Concrete Slab (200 / 150)        MITC4 shell facets
  Steel Plate 20                   MITC4 shell facet, 20 mm thick

What counts as grounded: a structural block whose DIRECTLY BELOW neighbour is a
solid, non-structural block. Nothing else grounds anything — a beam butted
sideways against a wall is not held by it, and the analysis will correctly call
the result a mechanism.

First case — a cantilever:

  1. Build a stone wall five blocks high.
  2. Put one Structural Steel block on TOP of the wall, then four more in a line
     out from it, into the air. The first one rests on stone, so it is grounded;
     the other four hang off it.
  3. Hold the Stress Glasses.
  4. Sneak-right-click the far end to apply a 20 kN test load. The same click
     removes it again.

Look at the beam and the section diagram appears in the corner: the stress
profile through the section depth, the neutral axis, and the extreme fibre
values in text.

Whether the top fibre is in tension or compression depends on the structural
form, not on the beam. A cantilever hogs, so its top fibre is in tension; a beam
supported at both ends sags, so its top fibre is in compression. Both readings
are correct, which is why the HUD states them in words rather than leaving them
to be inferred from colour.

Right-click the air to change lens: Utilisation -> Stress -> Material.

Cases worth trying:

  Nothing supporting it     reported as a mechanism rather than a structure.
                            Nothing is holding it up, so there are no stresses.
  Overloaded                max D/C rises above 1 and the member turns red.
  Tall slender column       stress D/C stays low while the buckling load factor
                            drops below 1. Strength and stability are different
                            questions.


COMMANDS
--------
  /br status         engine state, every path searched, last result
  /br members        per member: D/C, governing fibre, governing section, peak
  /br section <id>   per station, in text
  /br load <fx> <fy> <fz>   test load in kN on the block you aim at —
                     /br load 30 0 0 pushes a shear wall sideways
  /br unload [all]   remove the aimed block's test load / all of them
  /br loads          list every test load
  /br scan [radius]  re-read the chunks around you (default radius 4, so 9x9),
                     for blocks placed by command or WorldEdit
  /br resolve        force re-analysis
  /br reset          restart the engine after it has been disabled

  The four that CHANGE something — load, unload, scan, resolve — and reset
  need operator level 2. A single-player creative world has it already; in
  survival, or on a server without it, those commands do not appear at all.
  The Stress Glasses need no permission: they apply one configured downward
  test load. /br load takes any vector of any size, which is not the same
  thing.


SCOPE
-----
Implemented: 6-DOF beams, MITC4 shells including floors and shear walls, linear
buckling with geometric stiffness for both beams and shells, per-member and
per-shell D/C, surface stress contours.

Not implemented: the shell D/C is an elastic surface screen only — transverse
shear is recovered and reported but not screened, and there is no per-plate
buckling check and no plate ultimate strength. No composite reinforced-concrete
sections: the section catalogue is solid rectangles and circles, named so.
No nonlinear post-buckling — the buckling factor is the linear onset, an upper
bound on the real critical load.

Every solve returns a global equilibrium residual computed independently from
geometry and density rather than read back from the assembled load vector. The
verification record for this build - engine identity, every benchmark against
its closed form, cross-platform determinism and timing - is in the repository,
at evidence/VERIFICATION.md.
