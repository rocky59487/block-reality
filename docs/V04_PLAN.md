## 0. 這一版存在的理由（實測證據，v0.3b 發布版引擎）

玩家報告：「同片水泥被切塊、同根柱子被切，不符合自動成為一個結構的構想。」
對 `dist/br-sidecar.exe`（v0.3b）逐場景重現，全部成立，而且比描述的更糟：

| 玩家蓋的東西 | 模型實際變成 |
|---|---|
| 5×5 混凝土樑塊樓板（邊緣支承） | **40 根 1000 mm 短棒**；自重 221,314 N，**恰好是單向計重的 2 倍**（每格同時被 x、z 兩條 run 記重） |
| 2×2×6 厚柱 | **44 根 1000 mm 短棒**，縱橫皆被切 |
| 6×4 磚牆 | 38 根 1000 mm 短棒 |
| 4×4×2 疊兩層板材料樓板 | **32/32 unassigned，整個結構從分析裡消失** |
| L 型牆（板材料，用法正確） | **兩個獨立 island**，轉角一排 4 格 unassigned |
| 柱 + 樑同材質交會 | 柱斷成上下兩根 member（拓撲正確——交會處本該有節點；錯的是「一根柱子」的**物件身分**沒了） |

根因：抽取層只認得兩種形狀——1 維的線（樑材料 run）與恰好單層的面（板材料 2×2 方格）。
1000 mm 短棒 L/h = 1，正是不變式 1 自己劃的「樑理論不成立」線；`main.cpp` 的
plate-catalogue 註解早已描述過這個 grillage 缺陷，當時的答案是「板要用板 token」——
但玩家自然的蓋法（用混凝土塊堆牆、堆厚柱）全部踩中。

**為什麼先修判定再做倒塌**：算的歸算，演的歸演——演出層演的是判定層算出的失效集合。
在重量×2、短棒化、結構會消失的分解上蓋倒塌，是把錯的失效集合演得很漂亮。而且倒塌要
「整根柱子一起倒」，前提正是「一根柱子是一個物件」——聚合語意就是倒塌的地基。

## 2. v0.4 設計

### 2.1 材料類別

| 類別 | 材料 | 語意 |
|---|---|---|
| **frame** | steel、rebar、timber | 桿件是玩家放的線。方塊帶**軸向**（BlockState axis，放置時如原版原木決定）；run 只沿宣告軸抽取。並排/交叉不融合（§7.4 規則 4 不變——未螺栓的兩根鋼樑並排本來就不共同作用） |
| **plate** | concrete_slab_200/150、steel_plate_20 | 現行薄板語意不變：宣告厚度與 1 m 方塊解耦 |
| **monolith** | concrete、brick | **同材質面相鄰即融合成一個結構物件**；一格就是 1 m³ 的該材料 |

frame 的軸向宣告順帶從根源殺掉 grillage 雙倍計重：一個格子只屬於它宣告的那一條 run，
不再有第二條 run 搶同一格。蓋成面而軸向交錯的鋼樑陣照樣是格柵——但每格只記一次重，
而且那是玩家宣告出來的格柵，不是程式猜出來的。

**frame 接頭規則（補完，PR #60 審核 #5）**——每格只有一個軸，接合走兩條路：

- **跨軸交會**（T/L/X）：run 端點面相鄰於另一軸的 frame 方塊時，延伸到**該方塊的中心**
  共節點，並在該處切分對方的 run。X 型 = 兩條同軸 run 從兩側各自延伸到中央方塊中心，
  全部共用同一節點；剛性節點傳彎矩，連續性成立。單側延伸，無方向歧義。
- **同軸對接**（斷面或材料變更、端對端）：兩條 run 的節點都放在**共享面**上（D-028，
  半格座標）。絕不採「互相延伸到對方中心」——tectonic 現行 `extract.h` 正是這條規則，
  程式追蹤顯示它產出兩根重疊一公尺、不共任何節點的成員（§7.5，換裝前要修）。

既有的 `concrete_rect_400x600`（素混凝土「樑」）與 `brick_rect_230x350` 改為 monolith
——它們的 token 撒謊的部分（斷面與方塊解耦）本來就只對 frame 成立。v0.x 不承諾存檔相容，
照登在 release notes。

### 2.2 monolith 的融合與幾何分解

融合：同材質、面相鄰（6-conn）的 monolith 方塊集合為一個**區域**。對每個區域：

1. **稜柱判定**（整體）：沿某軸所有截面全等 → 整個區域是**一根 member**，斷面 =
   單位正方形聯集的真實斷面（2×2 柱 = 2 m × 2 m；L 型截面也成立）。這直接回答
   「同根柱子被切」。**條件收緊（PR #60 審核 #1——舊條件會把 6×4×1 的牆判成梁）**：
   走 member 須同時滿足 (a) 長度 ≥ 2 × 截面最大邊，且 (b) 截面兩維皆 ≤ 2（墩柱型）。
   6×4×1、10×4×1 → 牆（殼路徑）；2×1×8、2×2×6 → 柱 ✓。門檻值 M1 凍定，
   鏡像/旋轉 gate 盯裁決對稱性。
2. **逐格厚度分類**（否則）：每格沿三軸各量區域內 run 長 →
   恰一軸厚度為 1 = **面狀**；兩軸厚度為 1 = **線狀**；其餘 = **塊狀**。
   - 面狀連通子區域 → **MITC4 網格**，厚 1000 mm。轉角格（沿兩個法向厚度皆 1）
     **同時屬於兩片牆的網格**——L/T 牆因此在轉角共節點，folded plate 是標準解法。
     轉角格質量在兩片間均分（鏡像對稱要求；50/50 是唯一對稱解）。
     **轉角剛度（審核 #2）**：兩片網格各止於**中面交線**，不得雙雙鋪滿整個轉角體積；
     殘餘的重疊剛度照登為**轉角帶 indicative 級**——質量精確、力平衡精確（N6 不受
     影響），剛度在轉角一格內偏硬，白紙黑字。
   - 線狀子區域 → member（1 m × 1 m 斷面）。
   - 塊狀殘餘（D-030 修訂，2026-08-25 重裁）：**未接地** → `unassigned` +
     理由碼 `BULK_UNSUPPORTED`，質量不進模型但體積/質量列報，**永不靜默消失**；
     **接地** → 是**地**（v0.3b 墊塊語意的推廣）：固定面相鄰元素的介面節點，
     列報 `bulk-ground`——厚基座上蓋牆仍可分析。剛體質量塊改列引擎能力需求。
3. **介面**：子區域之間、與相鄰 frame/plate 元素之間，靠共用節點（方塊中心/面，
   沿用 D-028 半格單位）連接。

### 2.3 任意斷面性質

單位正方形聯集斷面：A、Iy、Iz、形心是精確整式。**非對稱斷面（L 型等）必算慣性積
Iyz 與主軸（PR #60 審核 #3）**：對 2×2 慣性張量取特徵向量得主軸角，構件局部座標
旋轉到主軸後以主慣性矩進引擎（FrameCore `Member.refVec` 可任意定向，M0 收尾項
驗證；tectonic 的 `axisRot` 現為四分之一轉，主軸角是它的推廣需求）。極端纖維距
cy/cz 在主軸座標系重算。只給 Iy/Iz 不給主軸的 L 型斷面，彎曲答案是錯的——
gate N12 用 L 型稜柱雙向載重釘死。

**扭轉常數 J** 的設計（文獻掃描第二批的結論，2026-08-24）：

- **雙式夾擠自驗**：Prandtl 應力函數 FD（Dirichlet，互補能）從下方逼近、warping
  function（位能極小，sectionproperties 的方法，MIT 授權可抄）從上方逼近——兩式各跑
  一次得到不需外部參考值的區間。（嚴格界只對 conforming FEM 保證，FD 版在 M1 先實測
  再宣稱。）
- **主 gate 用 n×m 矩形的 Timoshenko 精確級數**（單位邊長）：1×1 = 0.1406、
  2×1 = 0.4574、3×1 = 0.7899、4×1 = 1.1232、2×2 = 2.2492、3×2 = 4.699——涵蓋所有
  矩形聯集，走同一條組裝路徑。**薄壁疊加式 Σ⅓bt³ 不得當 gate**：對 2×1 高估 45%，
  t/b≈1 的方塊型斷面完全不適用。
- **L/十字型無公認閉合解**：用 sectionproperties 收斂值當黃金值 + 雙式夾擠交叉驗證，
  在 GATES.md 登記為**參考值 gate（結論低一級）**，不是解析 gate。
- **凹角兩條鐵律**（M1 凍 gate 時升格為正式決策）：(1) 凹角奇異性使 L/十字的 J 收斂
  掉到 O(h^{4/3})——容差按斷面凸性分兩類寫，**凹斷面禁用 h² Richardson**；(2) 凹角的
  理論剪應力無限大，任何網格下的局部峰值都是網格相依值，**不得進入 D/C 判定**——
  扭轉 D/C 對凹斷面用斷面級量 + 保守係數。
- **剪力面積 Av 是慣例相依的**（Cowper ν=0.3 矩形 κ=0.8497 vs Timoshenko/Hutchinson
  0.8667 vs 教科書 5/6）——慣例在 M1 凍死一種（預設 Cowper 1966）寫進 GATES.md，
  否則日後必出「沒 bug 卻過不了」的假輸格。

短胖 member（L/h < 3，例如 1×1×2 的墩）啟用 FrameCore 的 opt-in Timoshenko，
並在回覆帶適用性註記（INV-6 的路線，這次真的接出來）。

已查證（M0）：FrameCore 的 `Section` 是開放 struct——A/Iy/Iz/J/cy/cz/**Asy/Asz**
（Timoshenko 剪力面積）/Zy/Zz（塑性模數，v1 塑鉸要用）全部可直接填，`shape` 只決定
雙軸彎曲的合成法。聯集斷面沿用 `Rectangular` 的最壞角落和——對非凸斷面偏保守，
方向誠實（保守），照註記。

### 2.4 厚殼的適用界線

1 m 厚的 MITC4 是 Mindlin 板。文獻掃描第二批的裁定：驗收**拆成兩層**，混在一起會把
理論誤差誤判成元素 bug（MITC4 的病在薄極限 locking，不在厚極限）：

1. **元素 gate（閉合解，容差緊）**：對 FSDT Navier 解——簡支方板正弦載重
   `w/w_Kirchhoff = 1 + 5.6398·(h/a)²`（κ=5/6、ν=0.3、m=n=1），在 t/L = 0.1／0.25／
   0.5／1.0 四點測**元素本身**。（此式 M1 入 GATES 前對 Reddy 的 FSDT Navier 章複核。）
2. **理論 gate（業界標準）**：NAFEMS **LE10** 厚板基準——規格公開完整，目標值
   σ_yy = −5.38 MPa 於指定點。Srinivas (1969) 3D 彈性表為第三層選配（付費牆，
   數值未取得前不引用）。

**t/L 門檻是會拒絕的閘門，不是註解**（判準先凍：事後才加就是移線）：暫定
**t/L > 1/4 的殼結果降級為指示性**並在回覆註記——Mindlin 的公認適用界在 1/10 量級，
1/4–1/5 是誤差數個百分點的邊緣，t/L → 1 的東西是塊體不是板。實際門檻值 M1 凍定。
對玩家的意義：一格厚的 monolith 樓板要跨得夠遠（≳5 格）才有定量 D/C，短跨讀成指示性
——這與真實工程「那不是板是塊體」的判斷一致。

### 2.5 物件身分、損傷粒度與 chunk 規則

**融合區域（或 frame 的一條宣告 run）= 遊戲側的一個「構造物件」**；member/shell
是它內部的離散化。hover、`/br status`、未來倒塌的脫離單位，都以構造物件為單位。
柱+樑交會把柱切成兩個元素的事實不再滲漏到玩家面——玩家看到的是一根柱，帶一條
沿長度的 D/C 曲線。這也是 MEMBER_SEMANTICS §9.5「member 是持久物件」真正的落地點。

**粒度（審核 #4——「整棟一物件太粗」）**：物件是聚合與呈現單位，**不是失效粒度**。
損傷與斷裂記錄在**元素與方塊層**（DamageRecord 掛方塊集合，§9.5 原設計）；倒塌時
按斷裂面把物件切成**新物件**，lineage 保 ID 穩定——與 tectonic 的 fragment 模型
（斷 = 方塊離世 + 連通分量成塊）同構。一整棟相連混凝土是一個物件，但它可以局部
壞、局部掉，掉下去的那塊有自己的新身分。

**chunk 規則（審核 #7）**：分析範圍 = **registry 記錄的融合區域（持久）**，不是
「當前載入的 chunk」。區域跨到未載入 chunk → 該物件標 stale、分析延後，**永不**
因載入狀態被截斷重分類。gate N11 釘載入順序不變性：同一世界、不同載入順序 →
同一分解。

### 2.8 邊界紀律（D-033，開發期檢查表）

- **Java 只做四件事**：請求編排、物件身分簿記、渲染、演出。code review 時看到 Java
  出現內力/斷面/失效/分解字彙 = 違規。
- **adapter 不仿造**：sidecar 裡任何「引擎沒有、我先湊一個」的力學（高剛度假樑、
  假 MPC、自算應力）= 違規；缺 → 引擎側補或誠實拒絕。
- **gates 綁 wire**：新 gate 一律寫成「方塊進 → 回覆斷言」，不引用引擎內部符號；
  雙引擎並跑時同一套跑兩遍。

## 7. 既有方法對照（M0 文獻掃描，2026-08-24）

**存在性證明**：voxel → 梁+殼理想化有一條完整驗證過的先例管線——骨小樑生物力學的
**ITS-based Plate-Rod FE 模型**（Columbia）：二值體素 → thinning 骨架 → DTA 拓撲分類
（curve/surface）→ 完整體積分解（每個體素標記屬於哪片 plate 或哪根 rod）→ shell + beam
取代，模型尺寸縮小約 762 倍，模量與降伏強度對體素 FE 高度相關。**可行性來自輸入性質
（骨頭處處是薄的），不是演算法通用性**——這正是 D-030 把自動分解限定在 monolith 類別、
塊狀殘餘落到剛體塊的理由：與其在厚塊上硬造模型，不如判定「這不是薄的」然後誠實處理。

**方法選型（三條結論，直接約束 M3 實作）**：

1. **走距離場路線，不走 thinning 路線。** 精確平方 Euclidean 距離轉換
   （Saito–Toriwaki / Felzenszwalb–Huttenlocher）在整數格點上是精確整數運算——
   決定性與鏡像不變免費；局部厚度（Hildebrand & Rüegsegger）就是 CAD 降維
   「厚度比判準」在體素上的直接對應。反之 subiteration thinning 依固定方向順序掃描，
   有方向偏置，鏡像不變性不保證。§2.2 的逐軸 run 長分類是局部厚度的軸對齊簡化版，
   與此路線相容。
2. **線/面分類的嚴格版已存在**：Saha 等人的 digital topological analysis（DTA）
   用 3×3×3 鄰域的 tunnel/cavity 數把骨架體素分成八類（曲線/曲面/端點/接頭）——
   純局部、基於拓撲不變量。v0.4 的簡化分類若在畸形輸入上出現裁決歧義，這是升級路。
3. **業界公認的難點在接頭不在分類**：CAD midsurface 工具（CADfix、HyperMesh）的
   失效模式是 ill-connected midsurface（缺片、縫、重疊），修補以天計。本計畫把
   L/T 縫合（§2.2、N6）與 bulk 介面（R1）列為主戰場，與文獻的教訓一致。

**任何貪婪掃描（含 maximal-box 分解）的 x→y→z 順序都會破壞鏡像不變**——除非裁決
正則化。這把 N2 從「驗收項」升格為「設計約束」：每一條分解裁決都要先問「鏡像後這條
裁決還做同一個決定嗎」。轉角質量 50/50 均分是這個約束的第一個實例。

**遊戲界對照（查證於 2026-08-24）**：Medieval Engineers 是逐方塊應力啟發式 + 連鎖崩塌
（演算法未公開）；Space Engineers 明確不做；Teardown 是程序化碎裂非結構分析；
既有 Minecraft 結構 mod（Realistic Block Physics 等）是鄰居計數/支撐距離啟發式，
無勁度矩陣；唯一真 FE 的 Minecraft 案例（Purdue 教學工具）是體素即元素的連續體，
自承粗解。**對外文案的合規寫法**：「據我們所查，尚無遊戲以梁殼理想化的 FEA 做結構
判定」——帶查證日期，不寫絕對句；M7 時進 check_docs.py 禁句表管理。

**文獻掃描第二批（斷面與厚板，2026-08-24）**——結論已分別寫入 §2.3、§2.4、N4、N5。
補充事實與待確認：

- sectionproperties（MIT）的方法是 **warping function FEM**（Tri6，Lagrange multiplier
  處理純 Neumann 零空間），不是 Prandtl；它做 warping 前強制檢查斷面連通——「連通性
  是 J 的必要條件」與本專案不變式 4 是同一件事的兩面。
- 矩形 J 的精確級數出自 Timoshenko & Goodier《Theory of Elasticity》；本檔 §2.3 的
  六點表由該級數計算。
- NAFEMS LE10 的 t/L ≈ 0.09，屬中厚——它驗證元素，**不驗證極端厚的理論效力**，
  所以 §2.4 的降級門檻獨立於它。
- 待確認清單（凍 gate 前結案）：FSDT Navier 式對 Reddy 教科書複核；FD 版 Prandtl 是否
  嚴格下界；sectionproperties 的 Av 與 Cowper 的實際差距；NASA TP-3608 是否含 L 型
  高精度 J 值（PDF 未取得）。
