## P0 · Critical

### CONC-1 / FORGE-1 · 同一 session 開第二個世界必定崩潰 🔴

[AnalysisExecutor.java:54](../forge/src/main/java/com/blockreality/impl/server/AnalysisExecutor.java:54)

`POOL` 是 `static final`，只在類初始化建一次；`ServerStoppingEvent → shutdownAll() → POOL.shutdownNow()`
之後**永不重建**。單人模式退出世界 A 再開世界 B，玩家放下第一個結構方塊、約 10 tick 後
`StructureManager.tick()`（[StructureManager.java:263](../forge/src/main/java/com/blockreality/impl/server/StructureManager.java:263)）呼叫
`pool().execute(...)`，已關閉的 `ThreadPoolExecutor` 以預設 AbortPolicy 擲
`RejectedExecutionException`，從 `LevelTickEvent` handler 穿過 event bus（Forge 不吞 listener 例外），
整個 server 產 crash report 崩到主選單。**確定性重現：開世界A放結構方塊→退出→開世界B放結構方塊→crash。**
兩個維度的代理獨立發現並各自被覆核確認。

修法：pool 改掛 server 生命週期（ServerAboutToStart 建、ServerStopped 關），或 `pool()` 偵測
`isShutdown()` 就重建；`execute` 呼叫點包 `RejectedExecutionException` 並復位 `inFlight`。

## P1 · High

### A · 會壞掉的程式缺陷

**CONC-5 · 大型世界分析永久 livelock + 每 tick 恆定燒 8ms+**
[StructureManager.java:257](../forge/src/main/java/com/blockreality/impl/server/StructureManager.java:257)
snapshot 超過 8ms tick 預算時整份丟棄但狀態不變，下一 tick 原樣重跑。`structural` 集合只增不減
（卸載的 chunk 位置刻意「skipped, NOT forgotten」），世界大到一次 snapshot 超標之後：該維度分析
從此永不執行、無任何錯誤訊息，且主執行緒每 tick 恆定損失全額 snapshot 成本 → TPS 永久下降，無恢復路徑。

**TEST-3 · 測試荷載所在 chunk 卸載後，整個維度的分析靜默熄燈**
[StructureManager.java:301](../forge/src/main/java/com/blockreality/impl/server/StructureManager.java:301)
`snapshot()` 對未載入 chunk 的方塊 `continue`（跳過不移除），但荷載迴圈的守衛是
`structural.contains(pos)`——荷載進了請求、方塊沒進。引擎端（[main.cpp:1210](../sidecar/main.cpp)）
對「load on no structural element」整批拒絕（issue #14 的 fail-closed 設計），`apply()` 對 `!ok`
只發 status 就 return。結果：只要有測試荷載掛在會被卸載的 chunk，整個維度分析停擺且玩家無從得知。
覆核者親自沿呼叫路徑走過確認成立。這是 forge/ 零測試（見 TEST-1）漏掉的實際生產缺陷。

**CONC-3 · dimension unload 時 in-flight solve 會重新拉起 sidecar，程序從此無人管**
[SidecarClient.java:348](../mod/core/src/main/java/com/blockreality/core/sidecar/SidecarClient.java:348)
`close()` 把 status 設回 `IDLE`（不是終態）；已排入佇列的 task 之後執行 `ensureReady()` 看到
IDLE 就重新 spawn 一個全新 br-sidecar OS 程序＋shm region，但 manager 已從 `BY_DIMENSION` 移除，
tick/unload/shutdown 都碰不到它——孤兒程序只能等 JVM 端 Process 物件被 GC 才間接退場。

**FORGE-3 · 純樓板結構完全不畫應力覆蓋層**
[StressSurfaceRenderer.java:96](../forge/src/main/java/com/blockreality/impl/client/StressSurfaceRenderer.java:96)
`members` 為空就提前 return，但 `drawPlates` 不依賴 members。demo 只有兩種方塊，玩家只鋪
concrete_slab 不放 steel_beam 時，HUD 有數字、3D 等值圖一片空白——demo 內容的一半看不到。
