### A-1 · 不同材料的桿件永遠不共節點 🔴 critical

`sidecar/main.cpp:305-307`

### A-2 · CI 的引擎 gate 恆綠 🔴

`.github/workflows/ci.yml:28`

```yaml
python3 sidecar/verify.py dist/br-sidecar | tail -3
```

該 step 無 `shell:`、全檔無 `defaults:`。GitHub Actions 在 Linux 預設 `bash -e {0}`，**不含 pipefail**。

**端到端重現**（覆核者在 WSL Ubuntu 22.04 破壞 `verify.py:90` 讓一條 gate 真的紅）：raw 執行 `exit=1`；把 `ci.yml:27-28` 原封放進 `bash -e` → `exit=0`；加 `set -o pipefail` → `exit=1`。另兩個失效模式（interpreter 不存在、Python 例外）也各測過，全是 `exit=0`。

`ci.yml:1-3`、`GATES.md:98`、`RELEASING.md:60-61`、`FIX_ROLLUP:203` 全都把「CI 綠」當作這批 gate 的牙齒。**這是單點疏忽不是系統性習慣**——`scripts/package.sh:54` 是同一個 `python3 verify.py … | tail -1` 句型，但 `package.sh:23` 有 `set -euo pipefail` 所以安全；`release.yml` 也對。

**修法**：

```yaml
run: |
  set -o pipefail
  chmod +x dist/br-sidecar
  python3 sidecar/verify.py dist/br-sidecar | tail -3
```

或頂層 `defaults: { run: { shell: bash } }`（注意：只管 workflow，不管 shell 腳本——`package.sh` 的 `set -euo pipefail` 要保持）。**合併前故意讓一條 gate 失敗跑一次 CI，確認會紅。**
