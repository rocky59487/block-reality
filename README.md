# Block Reality

Minecraft 的結構工程沙盒。玩家用真實工法蓋房子，用真實力學知道它站不站得住。

三個構成：

- **設計層** — CAD 式的建造工具：polyline 繪製、精確尺寸輸入、osnap 吸附、全息預覽、變換 gizmo、delta undo
- **工法層** — 真實施工工序：綁筋 → 組模 → 澆置 → 養護 → 拆模。工序錯了有結構性代價，不只是視覺
- **力學層** — 真正的有限元素分析。6-DOF 樑柱 + MITC4 殼、稀疏直接解、per-member 內力與 D/C

力學引擎在 process 之外，透過凍結的 C ABI 呼叫。**換引擎不動 Minecraft 側**。

## 這個倉庫與前身的關係

前身是 `block-reality-api` 與 `PFSF-CORE`。本倉庫**只帶設計，不帶程式碼**。

前身的物理引擎 PFSF 每體素只有一個純量自由度，解的是穩態擴散方程而非彈性方程 —— 梯度的旋度恆為零，算不出純剪力與扭轉，也表達不了彎矩。這是結構性限制不是實作缺陷，因此整個力學層重做。

驗屍紀錄與六倉庫調查見 `docs/DECISIONS.md` D-001。

## 狀態

**力學層可用，設計層與工法層還沒開始。**

現在能做的事：放結構鋼與混凝土樓板 → 擷取成 6-DOF 樑與 MITC4 板 facet（含樓板與剪力牆）
→ FrameCore 求解 → 在方塊表面畫應力等值圖，並回報每根構件／每片板的 D/C **與線性挫屈的
臨界載重倍數**。

| | |
|---|---|
| 引擎驗證 | `sidecar/verify.py` **151 項**全過，全部對閉合解或不依賴求解器的不變量 |
| Java 驗證 | **107 項**全過，其中 28 項實際啟動 `br-sidecar` 跑真的 FrameCore |
| 對閉合解 | 31 項非零參考最差相對誤差 **1.6e-10**；10 項零參考最差絕對殘差 1.5e-08 |
| 板元素收斂 | 跨中 20 元素 **0.57%**；支承還原後 **2.7%** |
| 剪力牆 | 面內剪力流與傾覆軸力對閉合解 **1e-7** 等級 |
| 線性挫屈 | 對課本單元素柱值 **1.6e-05**；1/L² 關係 **2.3e-10** |
| 跨平台決定性 | **8/8 逐位元相同**（Linux 原生 vs Windows 交叉編譯） |
| 效能 | 199 根構件完整往返約 **50 ms**（含挫屈），且不在 tick 執行緒上 |

每一次求解的回覆都自帶**全域平衡殘差**（施加載重由幾何與密度獨立重算，不是從組裝後的載重
向量讀回來）。完整證據見 `evidence/VERIFICATION.md`，由 `scripts/evidence.py` 產生而非手打。

沒做的部分同樣寫清楚：殼的幾何勁度（所以挫屈只涵蓋樑柱，不涵蓋板的面內挫屈）、板的極限
強度、橫向剪力的 D/C 篩選、RC 複合斷面、非線性後挫屈路徑。

上手見 `QUICKSTART.md`。
